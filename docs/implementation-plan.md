- **Горячие клавиши.** Unity-шные `Ctrl+Shift+N` (создать пустой) и `Ctrl+N` (новая сцена) в

- **Этап 2.** Настройки открываются шестерёнкой в шапке, `Edit → Preferences` и `Ctrl+,`; последнее слушается в корне приложения, потому что должно работать и в текстовом поле, и на экране без рабочей области. Шаг привязки из настроек действует на гизмо перемещения (раньше в плашке вьюпорта было вписано «1.0»). Переключателя `UK / EN` на стартовом экране ещё нет — он появится с самим экраном в этапе 3.
- **Этап 3.** Экран выбирается функцией от состояния проекта (`AppStateService`); без открытого проекта рабочей области — и WebGL-контекста — нет. Проект больше не открывается сам после перезагрузки: браузер всё равно требует клик, поэтому стартовый экран показывает список недавних, а доступ запрашивается из клика (`openRecent`). Старая единственная запись проекта в IndexedDB не переносится.
- **«Создать проект» пока делает то же, что «Открыть папку»** (папка → вопрос → раскладка). Развести их — этап 4.
- **Панель Project больше не показывает «проект не открыт»**: она существует только при открытом проекте. Кнопка «Подготовить как проект сценария» убрана — это теперь вопрос при открытии папки.
- **Открытие проекта загружает `assets/scenes/main.scene.json`, если он есть.** Без этого Ctrl+S в уже готовом проекте записал бы пустую сцену поверх существующей. Сохранение новой сцены поверх чужого файла теперь спрашивает.
- **Закрытие проекта с несохранёнными изменениями спрашивает** (пока по `canUndo`; честный признак — этап 5).
- **Найдено при проверке production-сборки:** `for await` по `FileSystemDirectoryHandle.values()` в собранном бандле терял настоящую ошибку — при удалённой папке вместо `NotFoundError` приходил `undefined`, и пользователь видел «Something went wrong / undefined». В dev-сборке это не проявлялось. Обход папки теперь идёт вручную (`listDir`). **Следствие для проверок: e2e стоит гонять на production-бандле, а не только на `ng serve`.**
- **Этап 4.** Мастер из трёх шагов (о сценарии → с чего начать → где хранить) только собирает ответы; папку, раскладку и первую сцену создаёт вызывающий код, так что отмена на любом шаге ничего не пишет на диск. Адрес и имя папки следуют за названием, пока человек их не правит; адрес — транслитерация («Будова атома» → `budova-atoma`), потому что прежняя очистка просто выбрасывала кириллицу и давала `id: "scenario"`. Папка, где уже лежит что-то непустое с тем же именем, не затирается: мастер просит другое имя.
- **Первая сцена («Свет и камера») строится движком и сериализуется**, а не хранится готовым JSON: формат сцены задаёт движок. Камера с тегом `MainCamera` в `(0, 1, -10)`, солнце повёрнуто на `(50, -30, 0)`.
- **Проверено сквозь всю цепочку, кроме платформы.** `npm run e2e:build` копирует проект из мастера во временный сценарий ScenarioCreator, собирает ZIP и стриминговый манифест и запускает оба в движке через `verify-render.mjs`: оба пути грузятся и строят 2 объекта. Шаблонный `scripts/Scenario.ts` собирается без правок. Временный сценарий и всё, что сборка для него записала, удаляется. **Загрузка этого ZIP на платформу не проверялась** — Docker Desktop был выключен.
- **В меню File добавлен «New Project…».** «Создать проект» и «Открыть папку» на стартовом экране теперь разные действия.
- **Этап 5.** «Не сохранено» считается по счётчику правок истории (`HistoryService.revision`), а не по `canUndo`: тот остаётся true после сохранения. После отмены до сохранённого состояния сцена по-прежнему «не сохранена» — осознанно консервативно. Метка видна в строке состояния, у корня дерева, точкой у названия проекта и в заголовке вкладки. Закрытие и смена проекта/сцены спрашивают «Сохранить / Не сохранять / Отмена»; вопрос теперь задаётся **после** выбора папки или мастера, а не до, чтобы отмена выбора не оставляла «отброшенные» изменения.
- **Автосохранение** пишет `.editor/autosave.scene.json` раз в минуту, пока есть несохранённое (не во время игры); при открытии проекта предлагает вернуть, если копия новее файла сцены. «Не сохранять» и отказ от восстановления удаляют копию; таймер после «Не сохранять» молчит 5 с, иначе успевал записать её заново. Интервал для проверок переопределяется ключом `localStorage['wets:debug:autosaveMs']`.
- **Одна вкладка на проект — отказ, а не режим «только чтение».** Вторая вкладка не открывает проект и говорит почему: режим чтения затронул бы каждый путь правки. Блокировка (Web Locks) снимается при закрытии вкладки, так что упавшая вкладка проект не держит.
- **Изменения на диске** проверяются при возврате фокуса в окно: если здесь сцена чистая — перезагружается молча; если изменена и там и тут — вопрос «Перезагрузить / Оставить свою», и «оставить» не переспрашивается об одной и той же правке.
- **`DocumentService` не пишет файл сцены** — он только хранит состояние и таймеры; сохранение и вопросы остались в `CommandsService`, иначе сервисы зависели бы друг от друга по кругу. Вместо перенесённых `save/open` в нём `noteSaved/noteLoaded`.
- **Проект открывается только после раскладки** (`adopt(handle, layout)`): раньше рабочая область появлялась на мгновение раньше, чем создавались `scripts/` и `scenario.meta.json`.
- **Найдено и исправлено проверками этого этапа (все были и раньше):**
  - **Delete не удалял объект.** `destroy()` движка откладывает уничтожение до конца кадра, а редактор цикл движка не запускает. Теперь `destroyImmediate()`, как `DestroyImmediate` в Unity-редакторе.
  - **После каждой отмены в иерархии оставался «призрак»** старой сцены — та же причина.
  - **Перетаскивание гизмо не попадало в историю**: не отменялось и не отмечало сцену изменённой. Снимок берётся при нажатии на ручку, запись создаётся только если объект сдвинулся.
  - **Инспектор не показывал результат перетаскивания гизмо** (данные в сцене менялись, поле показывало старое): вычисляемые `pos/rot/scl` не зависели от ревизии.
  - **Клик по ручке гизмо без перетаскивания снимал выделение.**
  - **three.js сыпал ошибками**, когда гизмо оставался привязан к уничтоженному объекту.
- **К этапу 8:** Inspector оказался умнее, чем я писал в плане — секции компонентов уже строятся
  из метаданных движка (`getAllFields`). Остаётся «Add Component» с категориями из движка вместо
  ручного списка и редакторы для ссылок на ассеты.

## Этап 1 — каркас: состояния, настройки, язык, диалоги (4–5 дней)

Без этого этапа каждый следующий экран пришлось бы переделывать. Видимых новых возможностей
почти нет; результат — правильная основа.

### 1.1 Разделить `AppComponent`

| Новый файл | Что в него уходит |
|---|---|
| `app.component.ts` | Только оболочка: выбирает экран по состоянию, держит диалоги и настройки |
| `shell/topbar.component.ts` | Логотип, меню (в рабочем режиме), название проекта, кнопка настроек |
| `screens/start/start-screen.component.ts` | Экран «создать или открыть» (этап 3) |
| `screens/workspace/workspace.component.ts` | Нынешняя рабочая область: панели, сплиттеры, вьюпорт |
| `screens/workspace/toolbar.component.ts` | Панель инструментов |
| `screens/workspace/statusbar.component.ts` | Строка состояния |
| `services/commands.service.ts` | Действия (создать, удалить, копировать, сохранить…) — их сейчас вызывают и меню, и клавиши, и кнопки, каждый по-своему |
| `services/shortcuts.service.ts` | Один обработчик клавиш вместо `_onKeyDown` на 90 строк |

`ViewportService` привязывается к canvas рабочей области и отвязывается при уходе на
стартовый экран — иначе при закрытии проекта останется WebGL-контекст.

### 1.2 `AppStateService`

Одно состояние вместо разбросанных флагов:

```ts
type AppScreen = 'unsupported' | 'start' | 'workspace';
```

Вычисляется из `ProjectService.status()`. Игра и публикация — не экраны, а режимы внутри
рабочей области (этапы 10 и 11). Маршрутизатор не нужен: адрес у редактора один.

### 1.3 `SettingsService`

Настройки редактора, хранятся в `localStorage` под одним ключом `wets:settings:v1`:

| Настройка | Значения | По умолчанию |
|---|---|---|
| `language` | `uk`, `en` | по языку браузера, иначе `uk` |
| `theme` | `dark`, `light` | `dark` |
| `density` | `compact`, `comfy` | `compact` |
| `gridSnap` | число | `1.0` |
| `autosave` | вкл / выкл | вкл |
| `confirmDelete` | вкл / выкл | вкл |

Каждая — signal. Сервис сам ставит `data-theme` / `data-density` на `<html>` и атрибут `lang`.
`LayoutService` остаётся отдельным: размеры панелей — не настройка, а состояние.

Настройки относятся к браузеру, а не к проекту: в папку проекта не пишутся.

### 1.4 Язык: `I18nService`

- Словари — обычные TS-файлы: `i18n/en.ts`, `i18n/uk.ts`. Английский задаёт набор ключей,
  украинский типизирован как `Record<keyof typeof en, string>` — пропущенный перевод не
  соберётся.
- `t(key, params?)` читает signal языка, поэтому смена языка перерисовывает интерфейс сразу,
  без перезагрузки и без потери сцены. Встроенный i18n Angular не подходит: он выбирает язык
  при сборке, а не на лету.
- Вынести все строки из шаблонов и меню в словарь. Это самая объёмная часть этапа — механическая,
  но трогает каждый файл с шаблоном.
- **Не переводятся:** имена компонентов и полей движка (`MeshRenderer`, `fieldOfView`) — это
  имена из API, по ним ищут в документации; сообщения самого движка в Console.
- Добавить язык позже — один новый файл словаря.

### 1.5 Диалоги: `DialogService`

Замена `alert` / `confirm` / `prompt`: `confirm({...})`, `prompt({...})`, `open(Component)` —
возвращают Promise. Один контейнер диалогов в оболочке; Esc закрывает, фокус возвращается.
Нужен, потому что системные окна нельзя перевести, оформить и проверить автоматически, а
мастер, настройки и публикация без своих диалогов невозможны.

### 1.6 Светлая тема и плотность

Добавить в `styles.css` блоки `[data-theme="light"]` и `[data-density="comfy"]`. Значения
переменных взять из `design/wets.css` и `LIGHT_THEME` в `design/wets/app.jsx`.

**Готово, когда:** редактор выглядит и работает как раньше, но `app.component.ts` короче
150 строк; в шаблонах нет ни одной вписанной строки интерфейса; e2e-скрипт проходит.

## Этап 3 — стартовый экран и недавние проекты (2–3 дня)

**`ProjectService` дополняется:**

- `recents` — список `{ id, name, handle, openedAt }` в IndexedDB вместо одной записи; до 10

- `inspect(handle)` → `'project' | 'empty' | 'foreign'`: есть ли `scenario.meta.json`, пуста ли

- Автоматическое открытие последнего проекта убирается: после перезагрузки показывается
  стартовый экран с ним первым в списке и кнопкой «Продолжить».

**`screens/start/start-screen.component.ts`:**

- «Создать проект» → мастер (этап 4). «Открыть папку…» → диалог выбора.

  рабочая область. Папка недоступна → строка «не найдена» с предложением убрать.
- Открыли чужую папку (`foreign`) → диалог «В этой папке нет проекта. Сделать её проектом /
  выбрать другую». Пустую — сразу предложить мастер с этой папкой.
- Состояние `unsupported`: вместо кнопок объяснение про Chrome/Edge и HTTPS.
- Окно уже 1100 px — предупреждение.

File → Close Project возвращает сюда.

**Готово, когда:** без проекта рабочей области не видно; e2e: открыть → закрыть → проект в
недавних → открыть из недавних → убрать из списка.

## Этап 4 — мастер нового проекта (2 дня)

`screens/start/new-project-dialog.component.ts`, три шага:

1. Название, описание, категория (значения `ScenarioCategory` движка). Slug строится из названия
   с транслитерацией кириллицы — нынешний код в `initializeLayout` просто выбрасывает всё, кроме
   латиницы, и украинское название даёт `id: "scenario"`.
2. Шаблон: «Пустая сцена» · «Свет и камера».
3. Папка: диалог выбора, редактор создаёт в ней подпапку с именем проекта. Подпапка уже есть
   и не пуста — спросить другое имя.

`services/project-templates.ts` — содержимое шаблонов: `scenario.meta.json`,
`scripts/Scenario.ts`, первая сцена. Шаблон сцены создаётся кодом через движок и
сериализуется, а не хранится готовым JSON: формат сцены задаёт движок, и вписанный вручную
файл устареет при первом же его изменении.

**Здесь же проверить связку целиком:** собрать созданный проект в ScenarioCreator и открыть
ZIP на платформе. Шаблонный `Scenario.ts` сборщиком ещё ни разу не собирался.

**Готово, когда:** новый проект из мастера без ручных правок собирается ScenarioCreator и
показывает сцену со светом и камерой в `/play/`.

## Этап 5 — честное сохранение (2–3 дня)

**`services/document.service.ts`** — владеет открытой сценой:

- `path`, `dirty`, `lastSavedAt`. `dirty` ставится при любой записи в историю и снимается при
  сохранении. `HistoryService` получает счётчик изменений — сейчас индикатор смотрит на
  `canUndo()`, поэтому после сохранения он всё равно показывает «не сохранено».
- `save()`, `saveAs()`, `open(path)`, `newScene()` переезжают сюда из `AppComponent`.
- Перед `open` / `newScene` / закрытием проекта с несохранённым — диалог «Сохранить / Не
  сохранять / Отмена».
- `beforeunload` при `dirty` — предупреждение браузера при закрытии вкладки.

**Автосохранение:** раз в минуту при `dirty` пишет `.editor/autosave.scene.json`, основной файл
не трогает. При открытии проекта: автосохранение новее сцены → «Восстановить несохранённую
версию?». После обычного сохранения файл удаляется. Папка `.editor/` в ZIP не попадает
(панель Project и сборщик уже пропускают имена с точкой).

**Одна вкладка на проект:** Web Locks API с именем проекта. Вторая вкладка с тем же проектом
открывает его только для чтения и говорит почему.

**Изменения снаружи:** при возврате во вкладку — `ProjectService.refresh()`; если файл открытой
сцены изменился на диске — «Перезагрузить / Оставить мою».

**Готово, когда:** e2e: изменить → индикатор горит → сохранить → гаснет → изменить → открыть
другую сцену → диалог из трёх кнопок; закрытие вкладки с изменениями спрашивает; после
«падения» вкладки предлагается восстановление.
