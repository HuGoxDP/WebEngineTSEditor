# План: внешний вид и жизненный цикл редактора

Составлен 2026-10-07. Описывает, что пользователь видит и делает от открытия `/editor/` до
сценария в каталоге. Технические связи с движком и ScenarioCreator — в `integration-plan.md`;
визуальный ориентир — макет в `design/`.

Пользователь — преподаватель в Chrome или Edge. Проект — папка на его компьютере; на сервере
лежат только опубликованные сценарии.

> **Обновление 2026-10-09.** Жизненный цикл (§1) и экраны A, B, E (§2) действуют; стартовый
> экран, мастер и честное сохранение сделаны. Рабочее пространство (C) и игра (D) теперь
> описывает [`unity-editor-plan.md`](unity-editor-plan.md): образец — редактор Unity. Порядок
> работ (§4) и открытые вопросы (§5) заменены им же; вопросы из §5 решены.

## 1. Жизненный цикл

```
            ┌──────────────────────────────────────────────────────────────┐
            ▼                                                              │
   [A] Стартовый экран ──создать──► [B] Мастер нового проекта ──┐          │
            │                                                   ▼          │
            └──открыть / недавний──► (доступ к папке) ──► [C] Рабочее пространство
                                                                │   ▲      │
                                         Play ──► [D] Игра ─────┘   │      │
                                                  (Stop возвращает) │      │
                                         Publish ──► [E] Публикация ┘      │
                                         Close Project ────────────────────┘
```

| Состояние | Что на экране | Как попадают | Как выходят |
|---|---|---|---|
| **A. Старт** | Экран «создать или открыть», панелей нет | Открыли `/editor/` без проекта; закрыли проект | Создать → B; открыть → C |
| **B. Новый проект** | Мастер в три шага | Кнопка «Новый проект» | Готово → C; отмена → A |
| **C. Редактирование** | Все панели | Проект открыт | Play → D; Publish → E; Close → A |
| **D. Игра** | Вкладка Game, панели только для чтения | Play | Stop → C |
| **E. Публикация** | Диалог поверх C | File → Publish | Закрыть → C |

Правило, которое держит всё вместе: **без открытого проекта редактировать нечего** — рабочее
пространство не показывается. Сейчас редактор открывается сразу в C с пустой сценой и надписью
«no project»; сохранить работу в таком состоянии можно только скачиванием файла, и это первое,
что видит новый человек.

## 2. Экраны

### A. Стартовый экран

На весь экран, без панелей. Три блока:

- **Создать проект** — главная кнопка.
- **Открыть папку…** — системный диалог выбора папки.
- **Недавние** — список из IndexedDB: название, имя папки, когда открывали. Клик — браузер
  спрашивает доступ (один клик, это его требование) и открывает проект. У каждой строки —
  «убрать из списка». Если папку удалили или перенесли — строка показывает «не найдена», а не
  падает.

Внизу, мелко: «Проект хранится на вашем компьютере. В каталог попадает только то, что вы
опубликуете».

Отдельные состояния этого же экрана:

- **Браузер не подходит** (не Chromium или не HTTPS): вместо кнопок — объяснение, что нужно
  Chrome или Edge. Никаких полурабочих режимов.
- **Маленький экран** (уже ~1100 px): предупреждение, что редактор рассчитан на компьютер.

Что открытая папка — не проект (нет `scenario.meta.json`): предложить «сделать её проектом»
или выбрать другую. Не превращать молча чужую папку в проект.

### B. Мастер нового проекта

1. **Название и описание.** Название → автоматически slug (`id`, он же адрес `/play/<id>`),
   который можно поправить. Категория из списка движка.
2. **Шаблон.** Пустая сцена · Сцена со светом и камерой (по умолчанию) · позже — примеры
   по предметам.
3. **Где сохранить.** Диалог выбора папки; редактор создаёт в ней подпапку с именем проекта и
   раскладку (`scripts/`, `assets/scenes/`, `scenario.meta.json`).

После «Создать» сразу открывается C с первой сценой, уже сохранённой на диск.

### C. Рабочее пространство

Раскладка как в макете `design/`: меню и панель инструментов сверху, слева Hierarchy, в центре
Scene / Game, справа Inspector, снизу Project / Console, строка состояния внизу.

**Шапка.** Меню (File, Edit, GameObject, Component, Window, Help). Справа — название проекта и
имя сцены, точка «не сохранено», кнопка **Publish**.

**Панель инструментов.** Инструменты (рука, перемещение, поворот, масштаб) · Pivot/Local ·
Undo/Redo · **Play / Pause / Stop** по центру · привязка к сетке.

**Hierarchy.** Дерево объектов сцены, поиск, «+ Создать» с подменю (пустой, 3D-объект,
свет, камера, UI). Перетаскивание для смены родителя, глаз видимости, переименование по F2.

**Scene.** Вьюпорт: сетка, гизмо, выбор кликом, рамка выбора, F — показать объект. В углу —
куб ориентации. Пустая сцена подсказывает: «Добавьте объект: GameObject → 3D Object».

**Inspector.** Имя, включён/выключен, тег; Transform; по секции на компонент (сворачиваются,
меню «сбросить / удалить»); внизу «Add Component» с поиском. Ничего не выбрано — показывает
настройки сцены. Выбран файл в Project — показывает его (превью текстуры, параметры
материала).

**Project.** Папка проекта: дерево, содержимое, импорт перетаскиванием. Перетаскивание
отсюда: модель → в сцену, текстура → в слот материала, скрипт → на объект.

**Console.** Сообщения движка и редактора, фильтры, счётчик ошибок на вкладке. Ошибка
сохранения или публикации дублируется сюда, а не только всплывает.

**Строка состояния.** Готов / играет · число объектов · сохранено / не сохранено · FPS ·
версия движка.

**Сцены.** В проекте может быть несколько сцен; открыта одна. Какая из них стартовая —
отмечается в Project (правый клик → «сделать стартовой») и пишется в `scenario.meta.json`.

**Сохранение.**
- Ctrl+S пишет сцену в папку проекта. Точка «не сохранено» честная: сейчас она смотрит на
  «есть ли что отменить», а должна — на «менялось ли после сохранения».
- Автосохранение раз в минуту в `.editor/autosave.scene.json` — на случай закрытой вкладки.
  При следующем открытии: «найдена несохранённая версия, восстановить?».
- Закрытие вкладки или проекта с несохранённым — предупреждение.
- Смена сцены с несохранённым — «сохранить / не сохранять / отмена».

**Настройки проекта** (File → Project Settings): то, что лежит в `scenario.meta.json` —
название, описание, категория, версия, стартовая сцена, обложка для каталога.

**Настройки редактора** (Edit → Preferences): тема, плотность, язык интерфейса, шаг сетки.
Хранятся в браузере, к проекту не относятся.

### D. Игра

Play собирает сценарий так же, как для публикации, и запускает его во вкладке **Game** на
настоящем движке платформы.

- Панель инструментов подсвечена, строка состояния — «Играет».
- Сцена редактора не меняется: игра идёт в отдельном окне внутри вкладки. Stop просто
  возвращает вкладку Scene.
- Pause останавливает игру, Restart перезапускает.
- Ошибки сценария идут в Console.
- Если сцена не сохранена — Play сначала сохраняет.

### E. Публикация

Диалог в три шага:

1. **Проверка.** Список: есть стартовая сцена, есть камера, все типы компонентов известны,
   заполнены название и id, размер архива. Ошибки блокируют, предупреждения — нет.
2. **Доступ.** Поле для ключа публикации (хранится до закрытия вкладки).
3. **Отправка.** Прогресс, затем результат: «Сценарий загружен, пока скрыт от студентов» и
   ссылки «открыть в просмотре» и «перейти в админку, чтобы опубликовать».

Повторная публикация того же проекта обновляет тот же сценарий. Если на сервере уже есть
сценарий с таким id, которого этот проект не создавал, — спросить, а не затирать.

Рядом — **Скачать ZIP**: тот же архив файлом, без сервера.

## 3. Сквозные правила

- **Ничего не теряется молча.** Любая потеря (закрыть, сменить сцену, удалить файл, затереть
  сценарий на сервере) — с вопросом.
- **Доступ к папке.** После перезагрузки браузер требует клик. Редактор показывает это как
  одну понятную кнопку «Продолжить работу над „<проект>“», а не как ошибку.
- **Папку изменили снаружи.** Панель Project перечитывает папку при возврате во вкладку.
  Если открытую сцену изменили на диске — «перезагрузить / оставить мою».
- **Одна вкладка на проект.** Тот же проект во второй вкладке — предупреждение: две вкладки
  затирают сохранения друг друга.
- **Язык.** Платформа на украинском, редактор сейчас на английском. Нужно решить (§5).
- **Горячие клавиши** как в Unity (W/E/R, F, Ctrl+D, Ctrl+S, Ctrl+Z, Del), список — Help →
  Shortcuts.

## 4. Порядок работ

Каждый шаг заканчивается тем, что можно показать.

| # | Шаг | Что появляется | Оценка |
|---|---|---|---|
| 1 | **Стартовый экран и недавние** | A целиком; рабочее пространство только при открытом проекте | 2–3 дня |
| 2 | **Мастер нового проекта** | B; шаблон «свет и камера» | 2 дня |
| 3 | **Честное сохранение** | Точка «не сохранено», предупреждения, автосохранение, восстановление | 2–3 дня |
| 4 | **Создание объектов** | 3D-примитивы в меню и в «+» Hierarchy; подсказка в пустой сцене | 1–2 дня |
| 5 | **Несколько сцен и настройки проекта** | Стартовая сцена, форма `scenario.meta.json` | 2 дня |
| 6 | **Инспектор из метаданных движка** | Все компоненты редактируются; Add Component с поиском | ~1 неделя |
| 7 | **Ассеты в сцене** | Перетаскивание модели и текстуры, инспектор файла | ~1 неделя |
| 8 | **Play во вкладке Game** | D | 3–5 дней |
| 9 | **Публикация и скачивание ZIP** | E | 3–4 дня |
| 10 | **Оформление по макету** | Панель инструментов, инспектор и строка состояния как в `design/` | ~1 неделя |
| 11 | **Настройки редактора, язык, подсказки** | Preferences, перевод, список клавиш | 3–4 дня |

Шаги 1–5 — это «редактором можно пользоваться и не потерять работу», около двух недель.
Шаги 6–9 — путь до каталога; их технические детали — в `integration-plan.md` (фазы 3, 4, 6, 7).
Скрипты (фаза 5 там) в этот план не входят до решения ниже.

Уже есть: панель Project на настоящей папке, сохранение сцены в проект, запуск в Docker.

## 5. Что нужно решить

1. **Язык интерфейса.** Украинский, как платформа; английский, как Unity; или переключатель.
   Рекомендую переключатель с украинским по умолчанию — но закладывать перевод надо с шага 1,
   позже это переписывание всех шаблонов.
2. **Скрипты для преподавателя.** Пишет код сам или собирает сцену из готовых компонентов?
   Рекомендую второе: библиотека готовых поведений, без редактора кода. От этого зависит,
   нужна ли вкладка Code из макета.
3. **Вкладки макета, которых нет в плане:** Animation / Timeline, Code, Profiler, Packages.
   Рекомендую не делать, пока нет сценария, которому они нужны.
4. **Ключ публикации.** Сейчас это общий `ADMIN_TOKEN` платформы — тот же, что даёт удалять
   чужие сценарии в админке. Раздавать его преподавателям рискованно; нужен ли отдельный ключ
   «только публикация» — решение для платформы.
5. **Шаблоны проектов.** Достаточно «пусто» и «свет и камера», или нужны заготовки по
   предметам с первого дня.
